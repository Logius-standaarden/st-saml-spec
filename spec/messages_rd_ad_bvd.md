### OD→AD - SAML authentication proces {#rd-saml-authentication}

SAML authentication between [=OD=] and [=AD=] or [=BVD=] are described in this chapter. The [=OD=]→[=AD=]/[=BVD=] SAML messages are almost identical to the SAML messages of [DV/LC→OD - SAML authentication](#dv-saml-authentication). Therefor only a reference to the appropriate [DV/LC→OD - SAML messages](#dv-saml-authentication) will be given and the differences described.

#### OD→AD - Authentication - steps {#rd-saml-authentication-steps}

**Step 1, 2 and 3 (out of scope for this specification)**

For messages between [=AD=] and [=OD=] see [DV-OD authentication diagram](#dv-saml-authentication-diagram)

**Step 4 and 5**

The [=OD=] sends the [=EU=] to an [=AD=] for authentication or to a [=BVD=] for proof of representation (or both), using HTTP-Artifact. The browser carries a request artifact, not the AuthnRequest XML. Before processing the request, the AD/BVD resolves the artifact over mutually authenticated SOAP at the OD's ArtifactResolutionService. The OD returns an ArtifactResponse containing the signed AuthnRequest. The request and its artifact MUST be bound to the intended recipient and validated according to [[SAML2.BINDINGS]].

**Step 6 and 7 (out of scope for this specification)**

In these steps the [=EU=] interacts with an [=AD=] or a[=BVD=] .

**Step 8 and 9**

The [=AD=]/[=BVD=] sends the [=EU=] back to the [=OD=] via a browser redirect. An opaque [=Artifact=] generated by [=AD=]/[=BVD=] is send here in the [Artifact Response message](#rd-artifact-response). The [=Artifact=] refers to the actual [SAML response message](#rd-authn-response-message) that is waiting at [=AD=]/[=BVD=].

Even if the interactions in step 6 and 7 were unsuccessful or cancelled, an [=Artifact=] is send to the [=OD=]. This [=Artifact=] provides an error message with the [Artifact Resolve message](#rd-artifact-resolve-message) and cannot be exchanged for a valid [Assertion](#rd-authn-response-assertion).

**Step 10**

With the [=Artifact=] the result of the (successful or unsuccessful) authentication or representation can be retrieved from the [=Back channel=].

An [Artifact Response message](#rd-artifact-response-message) is valid for a maximum of 15 minutes and can only be retrieved once by the [=OD=]. Situations are possible (process breakdown, early logout) where an [=Artifact=] is valid less than 15 minutes.

**Step 11**

[=AD=]/[=BVD=] replies with an [Artifact Response message](#rd-artifact-response) that belongs to the [=Artifact=]. In this message, [=AD=]/[=BVD=] provides an [Assertion]( #rd-authn-response-assertion) that includes the authentication result or the proof of representation. And, if the authentication / representation selection was successful, the requested (encrypted) identifier(s) and attribute(s) of the [=EU=] or the [=Represented Party=]. The identities and attributes are encrypted so that only the intended [=DV=]\(s\) can obtain the plain text value.

If the authentication or attempt to select representation was unsuccessful, it is indicated in the Status Code of the Response message and if possible, a reason is given so that the [=DV=] can inform the [=EU=].

### OD→AD - SAML messages

> 1. The messages contain at least the elements that are specified as mandatory by the standard.
> 1. In addition, the messages also contain optional elements. It is indicated whether these elements are mandatory, conditional or optional. With optional elements, it is up to the participants to determine whether they are used.
> 1. Optional SAML elements that are not in this specification SHOULD NOT be included. When present they will be ignored when possible.


#### OD→AD AuthnRequest {#rd-authnrequest} 

When a principal (or an agent acting on the principal's behalf) wishes to obtain assertions containing authentication statements to establish a security context at one or more relying parties, it can use the authentication request protocol to send an [AuthN Request message](#dv-authn-request-message) message element to a SAML authority and request that it returns a [AuthN-Response message](#dv-authn-response-message) containing one or more such assertions.

##### OD→AD request artifact binding {#rd-request-artifact-binding}

The OD publishes the ArtifactResolutionService used to resolve request artifacts in its SPSSODescriptor. The AD/BVD MUST obtain that endpoint from validated OD metadata and authenticate the OD on the back channel. The OD MUST authenticate the resolving participant, enforce the artifact's intended recipient and one-time use, and return only the matching request. The AD/BVD MUST validate the ArtifactResponse and the signed AuthnRequest before processing the request; a browser-supplied artifact alone does not establish trust. The AuthnRequest's AssertionConsumerServiceIndex selects the registered OD response endpoint, independently of AttributeConsumingServiceIndex.

##### OD→AD AuthnRequest Processing rules {#rd-authnrequest-processing-rules}

The AD MUST validate the OD's signature and metadata, the intended DV and the registered service referenced by ServiceID and ServiceUUID in the OD's Extensions. The LC is not the issuer of this downstream request. Authorization of the LC is checked by the OD before constructing the downstream request; it MUST NOT be delegated to the AD. A failed validation MUST fail authentication.

#### OD&larr;AD Response - Artifact Binding {#rd-response-artifact-binding}

The SAML response of a [=AD=] or [=BVD=] to a SAML request of a [=OD=] uses an [=Artifact=]-Binding for extra security see  [[SAML2.BINDINGS]] section 3.6.6. Therefor SAML Response does not return the actual SAML message with an Authentication Assertion but an [=Artifact=] as a reference to actual the SAML [AuthN Response - Assertion](#dv-authn-response-assertion) message. The OD uses the artifact to retrieve the matching response at the issuing AD/BVD over the mutually authenticated SOAP back channel.

##### OD&larr;AD Response - Artifact Binding - Message {#rd-saml-response-artifact-binding-message} 

The receiver of the previous [AuthN Request message](#rd-authn-request-message) sends a SAML [=Artifact=] message via the front channel by a redirect to the [=rd-sp-entitydescriptor/AssertionConsumerService=] referenced in the [AuthN Request message](#rd-authn-request-message). An [=Artifact=] is a reference to the SAML [AuthN Response - Assertion](#rd-authn-response-assertion) message. Even if no authentication has taken place, an Artifact will be send. The Artifact message is send to the recipient via an HTTP Redirect. The [=Artifact=] is used by the receiver to retrieve the SAML [AuthN Response - Assertion](#rd-authn-response-assertion) at the sender.

#### OD→AD ArtifactResponse {#rd-artifact-response}

The [AuthN Response message](#rd-artifact-response-message) contains the response message to the [Artifact Resolve](#rd-artifact-resolve-message) request in a SOAP message. This response message in turn contains the [AuthN Response - Assertion](#rd-authn-response-assertion) to the Original [AuthN Request message](#rd-authn-request-message). The sender will send the [AuthN Response message](#rd-artifact-response-message) in response to an [Artifact Resolve](#rd-artifact-resolve-message) request. If successful it contains the [AuthN Response - Assertion](#rd-authn-response-assertion) to the [AuthN Request message](#rd-authn-request-message).
